# Curator Save

Используй этот skill, когда нужно извлечь знания из текущей сессии и сохранить
их в личную базу знаний через Memory Curator.

## Выбери формат: карточка или файл

- **Карточка** - точечное знание с самостоятельной ценностью (правило,
  паттерн, принцип, который нужен отдельно от темы). Единица записи -
  секция `###` в тематическом файле.
- **Файл-знание** - опыт целой сессии по одной теме (теория + грабли,
  как устроен инструмент). Одна тема = один файл = одна причина
  изменения (SRP). Модель пишет файл сама, куратор фиксирует.

Точечное знание → карточка. Опыт сессии по теме → файл-знание.
Смешанные форматы в одном файле (вводная теория + карточки-грабли) -
норма, не дели.

## Короткий flow (fast lane)

1. Собери кандидатов - сначала из леджера задачи (если есть), потом из
   контекста сессии - по правилам из `playbook.md`. Выбери формат
   (карточка / файл-знание).
2. Карточки: один вызов CLI `curator save --yes` с JSON в stdin. CLI сам
   валидирует формат, ловит дубликаты, резолвит маршрут по карте базы
   (`knowledge-map.md`), пишет markdown + индекс и журнал аналитики,
   затем делает локальный git-коммит (без push). Если тематический файл
   очевиден - передай в кандидате `source_file` (например
   `reference/architecture.md`), иначе маршрут уйдёт в дефолт `session/*.md`.
3. Файл-знание: запиши/дополни файл в базе (путь по карте тем), затем
   `curator save --doc <path>` - куратор сверит путь с картой, закоммитит
   и запротоколирует в журнале аналитики.
4. Покажи пользователю итог из вывода CLI: что сохранено и куда (строки с
   «→ файл»), что отклонено и почему.
5. Корректировка формулировки - повторный вызов с тем же title: секция в
   файле обновится, дубля не будет (upsert).

Никаких MCP-инструментов: флоу целиком через bash.

Полный workflow - в `playbook.md` рядом с этим файлом. Прочитай и выполни
его целиком. `SKILL.md` - только точка входа.
