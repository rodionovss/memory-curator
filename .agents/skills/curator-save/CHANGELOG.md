# Changelog

## 0.5.0

- Два формата записи: карточка-секция (точечное знание с самостоятельной
  ценностью) и файл-знание (опыт сессии по теме; SRP: одна тема = один файл
  = одна причина изменения). Смешанные форматы в одном файле - норма.
- `curator save --doc <path>`: модель пишет/дополняет файл, куратор
  проверяет путь по карте, коммитит и пишет событие в журнал аналитики.
  Контент всегда пишет модель; куратор - библиотекарь.
- Шаблоны в плейбуке: файл-темы (теория + грабли) и карточки
  (правило + почему + когда).
- Поле `evidence` убрано из контракта: доказательность живёт в самом
  `content_summary` (правило + почему), ссылки на мутабельные файлы гнили.
- Карта базы переименована: `knowledge-map.md` (legacy `DOCUMENTATION-MAP.md`
  поддерживается). Каталог `knowledge-routes.md` теперь проекция карты.

## 0.4.0

- `source_file` в контракте кандидата: передавай, когда тематический файл
  очевиден - без него DefaultRouter кладёт всё в `session/*.md` (найдено
  на практике: 4 факта уехали в дефолт).
- `curator save` после записи делает локальный git-коммит базы (без push):
  база пишется автоматами без ревью, git даёт diff и точечный откат.
- Починен флаг авто-подтверждения: доки говорили `--auto-yes`, CLI принимал
  только `-y`/`--yes` - агент по доке падал в интерактивный промпт. Теперь
  `--yes` (канонический) и `--auto-yes` (алиас) оба работают.
- Отдельные темы (vpn/, проекты со своей папкой) - не в личную базу;
  маршрут уточнять у пользователя.

## 0.3.0

- Пивот 2026-10-03 (см. ../../decision-log.md): MCP-церемония
  (`curator_session_capture` → approve → `curator-update-docs` → complete)
  заменена одним вызовом CLI `curator save --auto-yes`.
- Кандидаты в первую очередь берутся из леджера задачи харнесса
  (у OpenCode: `.opencode/features/<task-id>/progress.md`), контекст сессии - fallback.
- Контент-контракт усилен: Rule + Why + условие применения (было 1-2
  предложения - контекста не хватало).
- Корректировки: повторный вызов с тем же title = upsert секции, не дубль.
- Проектные знания (docs/ai репо) явно отделены от личной базы.

## 0.2.0

- Разделён trigger-wrapper `SKILL.md` и подробный `playbook.md`.
- Добавлена последовательная проверка изменения понимания, evidence,
  переносимости, атомарности и типа утверждения.
- Сохранён read-only protection; сохранение переведено на flow
  `curator_session_capture` → `curator_capture_approve` →
  `curator-update-docs` → `curator_capture_complete`.
- Версия принята по итогам A/B (см. `benchmark/extraction/`): строгость
  фильтров подтвердилась — отсев провизорных деталей без потери
  подтверждённых знаний.
