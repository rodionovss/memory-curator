# Knowledge Route Metadata — контракт маршрутов уровня файла

Каталог `knowledge-routes.md` — сгенерированный Markdown-указатель, который
доставляется агенту (в workspace/глобальный AGENTS.md, по решению ADR 003 —
routing-слой как primary delivery path). Каталог содержит **только
метаданные для маршрутизации** — никогда полное содержимое фактов.

Терминология: это **Knowledge Route Metadata**, не Skill. Маршрут —
указатель на источник, не исполняемая инструкция.

## Гранулярность: один маршрут = один `source_file`

Один route entry представляет один `source_file`, а не один факт.
Тематические Markdown-файлы, в которых много фактов, не разбиваются:
агенту нужен указатель «какая база знаний закрывает эту тему», а не
копия индекса. Разбиение по фактам — задача retrieval-слоя
(per-fact SQLite-индекс), не routing-слоя.

## Поля route entry

| Поле | Что содержит |
|------|--------------|
| `Description` | Краткое описание темы файла: о чём база, одним-двумя предложениями |
| `When to use` | Список ситуаций, когда агенту следует свериться с этим файлом |
| `Contains` | Список тем внутри файла — из заголовков секций (`### ...`) |
| `Source` | Путь к `source_file` относительно корня базы |

Схематичный entry (значения иллюстративные):

```md
## <Имя темы>

**Description:** <о чём файл, кратко>

**When to use:**
- <ситуация 1>;
- <ситуация 2>.

**Contains:**
- <заголовок секции 1>;
- <заголовок секции 2>.

**Source:** `<path/to/file.md>`
```

### `Contains` — из заголовков секций, не из `content_summary`

`Contains` строится из заголовков секций исходного файла (`### ...`),
как они попадают в `StructuredFact.title` при ingest. Это НЕ копия
`content_summary`: маршрут должен быть короче факта, иначе каталог
деградирует в дубликат базы. `Description` и `Contains` отвечают на
«что внутри», `When to use` — «когда открыть», `Source` — «где лежит».
Этого достаточно, чтобы агент решил, читать файл или нет, без
переноса самого содержимого в контекст.

## Отношение к SQLite: routes — уровень файла, rows — уровень факта

Markdown остаётся source of truth; SQLite (ADR 001) — производный
per-fact retrieval-индекс. Контракты не смешиваются:

- **route entry** — один на `source_file`, только метаданные,
  для решения «какой файл открыть»;
- **SQLite row** — один на факт, с `content_summary`, статусами,
  provenance, для retrieval и improve-цикла.

## Правила валидации

- **Факт без `source_file` — ошибка валидации.** Такие факты
  попадают в отчёт генерации каталога и видны человеку; молча
  пропускать их запрещено. Маршрут без источника — указатель в никуда.
- **Deprecated-факты исключаются из активных маршрутов.** Каталог —
  окно в живую базу: то, что решено удалить, не должно попадать
  в контекст агента. Статусы фактов знает только SQLite — поэтому
  генерация каталога идёт с учётом статусов, а не простым scan
  Markdown-файлов (Markdown scan проигрывает по статусам — ADR 003).
