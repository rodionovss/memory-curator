## Подтверждено жюри (спринт)

Приоритеты из фидбека жюри Hacker Sprint #2 и полевых уроков
([пост-мортем](postmortem-hacker-sprint-2.md)):

- **Push-доставка с relevance gate**: надёжный автоматический подбор и
  доставка нужного знания в контекст задачи вместо ручного pull
  (curator_query). Наш кейват: retrieval промах 9/10; главный гэп по
  вердикту жюри и полевому уроку «качество retrieval важнее объёма».
  Паттерн-референс: Marginal Gain (вес × уместность, порог, лента молчаний)
- **Масштаб эвала**: больше задач/доменов/прогонов — снять ограничение
  «масштаб вывода» (сейчас 10 задач, 6 дискриминаторов, N=1 основного
  прогона; у победителя — 50 held-out сценариев с paired-статистикой)
- **Эвал качества извлечения**: детерминированная оценка того, что
  curator-save извлекает подходящих кандидатов (доля полезных, пропуски,
  шум) — паттерн-референс: observer-эвал Cadence
- **Метрика применения в improve-петле**: eval-гейт консолидации сегодня
  мерит состояние базы (coverage, stale_percent) — «чище» ≠ «агент решает
  лучше». У петли нужна метрика применения (знание дошло до задачи /
  применилось), гигиена — только прокси. Полищук: «проверки состояния
  базы сами по себе ещё не показывают улучшение агента»; полевой урок №2:
  обучение = устойчивое изменение поведения

## Из gold-ревью базы (2026-09-16)

Находки ревью 116 legacy-фактов майнинга ([gold-отчёт](../docs/superpowers/reports/2026-09-16-legacy-review-gold.md)):

- **Дедуп gatekeeper слеп к семантическим дублям**: Jaccard по заголовкам
  (порог 0.7) не поймал ни одной из 5 дословных пар пула (максимум сходства
  0.33 — «Verbose-логирование» ×2, «endsWith» ×2, «Тап по строке» ×2 и др.;
  все найдены только семантическим чтением). Дубли, написанные разными
  словами, проходят насквозь. Кандидат: similarity по content_summary +
  нормализация словоформ, либо LLM-дедуп как отдельный gate
- **Фильтр «неочевидно сильной модели» для extraction**: 40% пула — `low_value`
  (главный лейбл ревью: знания, которые сильная модель знает сама).
  Gatekeeper-фильтр «абстрактно/подтверждено» это не отсекает. Gold-критерий
  планки пользователя: знание живёт в базе, только если (а) из его
  ежедневного стека, (б) неочевидно сильной модели, (в) меняет поведение
  агента — референс для эвала качества извлечения

  едут внутри пакета (package data), установщик распаковывает их из себя

## Командная работа

- **`curator pull`**: слить чужие факты из xmemory в локальную базу.
  Сегодня `curator sync` — только push (наш outbox → xmemory); pull —
  первая ступень полноценной синхронизации

## Извлечение знаний

- **Прошлые сессии**: разговор закрыт и забыт — знания из него можно
  вытащить позже одной командой (сейчас работает только текущая сессия
  через `/curator-save`)
- **Auto-trigger**: извлечение после закрытия сессии (hooks харнеса) —
  «я об этом не думаю, знания сохраняются сами»
- **Per-fact approve**: подтверждать кандидатов выборочно (номерами) и
  править до сохранения
- **Project-scoping**: поле project у факта — разные базы для разных
  проектов

## Тех.долг

Замечания из ревью интеграции карты документации (МР #1):

- **Pending captures на диск**: одобренные capture живут в памяти процесса
  (OrderedDict + LRU 100) — рестарт сервера теряет их, два клиента не видят
  чужие capture_id. Сериализовать в state dir
- **xmemory-валидация типов**: backend/xmemory.py принимает любую строку
  как тип (было: молчаливый фолбэк на Reference) — валидировать против
  реестра типов, чтобы не ловить типовой дриф
- **Windows-тесты вне CI**: test_windows_compatibility.py никогда не
  выполняется автоматически (CI ubuntu-only). Либо windows-runner, либо
  осознанно признать тестами-документацией
- **Хрупкие test_skill_contracts.py**: ассерты на дословные фразы SKILL.md
  (включая переводы строк) — редактура текста скилла ломает тест.
  Ослабить до контрактов на структуру
