# Направления развития

Сделанное живёт в main и README; здесь — только будущее, коротко.

## Установка и упаковка

- **pipx/uv**: установка одной командой без клона репо — скиллы и команды
  едут внутри пакета (package data), установщик распаковывает их из себя

## Командная работа

- **`curator pull`**: слить чужие факты из xmemory в локальную базу.
  Сегодня `curator sync` — только push (наш outbox → xmemory); pull —
  первая ступень полноценной синхронизации

## Извлечение знаний

- **Прошлые сессии**: разговор закрыт и забыт — знания из него можно
  вытащить позже одной командой (сейчас работает только текущая сессия
  через `/curator-save`)
- **Auto-trigger**: извлечение после закрытия сессии (hooks харнеса) —
  «я об этом не думаю, знания сохраняются сами»
- **Per-fact approve**: подтверждать кандидатов выборочно (номерами) и
  править до сохранения
- **Project-scoping**: поле project у факта — разные базы для разных
  проектов

## База знаний

- **Двусторонняя .md-синка**: правка файла руками → авто-переиндексация
  (ingest уже умеет, нужен watcher-триггер)

## Self-improvement

- **Приём репортов ядром**: баги/идеи от агентов сессий — через MCP-тул
  (валидация контракта, дедуп) вместо файлового беклога и промпт-контракта
  скилла-репортёра; контур самоулучшения — см.
  [docs/self-improvement-loop.md](../docs/self-improvement-loop.md)
- **RBAC**: структурные права на правки репо для агентов (сегодня —
  контракты + pre-commit hook, защита от «случайного» агента)
