# Decision Log

Живой журнал решений проекта Memory Curator: что обсуждали, что решили, что сделали и почему. Отменённое фиксируется с причиной. Новые записи добавляются сверху.

Предыстория до хакатона (эпоха xmemory) - в `design/decision-log.md`. Глубокие решения с данными - в ADR: `design/decisions/001-sqlite-only-storage.md` (SQLite-only), `design/decisions/002-delivery-contract.md` (транспорт-агностик delivery), `design/decisions/003-delivery-decision.md` (shadow-режим и выбор placement).

## 2026-11-21 - README по образцу archspec: честный install, MIT, Why + диаграмма

Сверка с README krus210/archspec, формат одобрен владельцем. Решения:

- **Install = clone + editable.** Главный путь из README был сломан:
  `uv tool install ./core` (без `-e`) кладёт пакет в site-packages без
  `integrations/` и `.agents/`, инсталлер молча ставил пустоту и печатал
  «Готово». Теперь guard `RepoAssetsMissingError` падает громко с подсказкой
  рабочего пути (git clone → `uv tool install --force -e ./core`).
  Альтернатива - упаковка integrations в wheel (package-data) - отвергнута
  до появления цели PyPI: для репо «built for myself» лишняя работа;
  плагин-обёртка (хук-бутстрап, без MCP) отложена (лестница
  ступеней - ниже в этой записи).
- **Лицензия MIT** - как у archspec: файл LICENSE + бейдж + секция в README.
- **README дополнен**: Mermaid-диаграмма save-флоу (single source of truth =
  knowledge-map.md) и секция Why - таблица «Боль → ответ» живыми симптомами.
- **Репозиционирование: публичный open-source.** «built for myself»
  убрано из README: проект - общее решение, кто хочет - берёт,
  контрибьютит. Инсталлер и упаковка делались не «под себя», а под
  чужое использование.
- **Backlog снесён из репо.** Публичный файл будущих фич не нужен,
  пока нет списка «обсудили и точно будем делать»; живая задача одна -
  улучшение детекции знаний (119/488 отклонений gatekeeper, данные в
  analytics.jsonl) - перенесена в локальный backlog (design/backlog.md,
  вне git). Компакт-хук (идея 2026-11-14: сохранение в момент компакта
  сессии) отменён как невостребованный. Лестница install-ступеней
  (wheel-упаковка → плагин-обёртка без MCP) остаётся здесь, в журнале:
  актуальна при появлении цели PyPI.
- **Финальное ревью вскрыло разрыв «README обещает - код не делает»**:
  свежая база не была git-репо, и провал коммита молчал («✅ Сохранено»
  без истории). Решено: `_git_commit` сам инициализирует репо базы
  (`_ensure_git_repo`; база внутри чужого репо не трогается) и возвращает
  committed/noop/failed; провал виден ⚠-строкой в save; отказ инсталлера
  завершает CLI с exit code 1 (для скриптов); подсказка guard'а
  синхронна с README-флоу (clone → cd → `-e ./core`).

## 2026-10-06 - «библиотекарь, не писатель»: два формата записи, одна карта

Дискуссия о будущем формата на живом опыте VPN-сессии. Владелец пришёл к выводу
самостоятельно (совпало с гипотезами A/B от 03.10): единица хранения - смешанная,
«факты и статьи живут рядом». Критерий выбора - самостоятельная ценность знания
(Zettelkasten-атомарность): кросс-темное правило → карточка; грабли темы →
файл-тема. Рамка SRP от владельца: **одна тема = один файл = одна причина
изменения** - файл-тема и есть «один факт», просто составной.

Главное прояснение: **контент всегда пишет модель** (и карточки, и файлы) -
куратор никогда не был писателем. Куратор - библиотекарь: карта (куда), дедуп
(что уже есть), git (что изменилось), журнал аналитики (что сохраняется).
Отсюда решение: `curator save --doc <path>` (0.5.0) - модель пишет файл,
куратор проверяет путь по карте, коммитит, протоколирует. В SQLite не пишет:
файл-знание сам себе единица. Вариант «проза руками мимо куратора» отклонён
как два пути записи.

Карты: `DOCUMENTATION-MAP.md` (write-карта, вклад Егора) и `knowledge-routes.md`
(read-каталог, наш) дублировали друг друга («содержание внутри содержания»).
Решено: **карта = единственный источник истины** (переименована в
`knowledge-map.md`), каталог - генеримая проекция (таргеты карты + заголовки
фактов из DB). `index.md` оставлен; кандидат на удаление после обкатки.
Проекция вскрыла и починила рассинхронизацию: 9 файлов с фактами, не известных
карте (легли до неё), - темы доведены до полноты.

Прочее: поле `evidence` убрано из контракта (ссылки на мутабельные файлы
гнили; доказательность = «правило + почему» в самом описании). Карточки
телеметрии переименованы в журнал аналитики (`analytics.jsonl`). VPN перенесён
в базу: `~/Documents/AI/vpn/` → `learnings/vpn/` (VPN - тоже learning, не
отдельный проект). README переведён на тон «stable, build for myself».
Карта получила mihomo/sing-box/xray в триггеры (факт от 04.10 не совпал бы
со старой темой vpn - живая дыра слов-триггеров).

**Backlog (не решения, условия запуска):**
- **Эмбеддинги** (локальная модель-энкодер ~100 МБ): убивают `watch_for`
  (тема представлена содержимым, карта сжимается до 2 строк на тему и
  перестаёт расти) и ловят синонимы в дедупе («VPN рвётся» ≈ «VPN
  отключается»). Запуск: база заметно вырастет или поддержка триггеров заболит.
- **Ссылки между заметками** (Zettelkasten-элемент, markdown-ссылки в
  описаниях): ценность на большой базе (чтение по связям), сейчас проблемы
  не решает - принципиально отложено по эссенциализму.
- **index.md**: удалить, когда проекция карты докажет себя в чтении.

**Смоук вскрыл главную причину misroute:** `ROUTER_CLASS` не был задан нигде
(launchctl, .zshenv, plist) - MapRouter был мёртвым кодом в проде, все факты
маршрутизировались DefaultRouter'ом (source_file если передан, иначе session/).
pyyaml-баг 04.10 был вторичен. Фикс: MapRouter теперь дефолт при наличии
карты в базе (без env); ROUTER_CLASS остался как явный override. Живой
смоук подтверждает: тег mihomo → тема vpn → `vpn/nodemaven-clash.md`.

**Статус: 0.5.0 - один вход (карточки + save --doc), одна карта (источник +
проекция). A/B скиллов (curator-save vs save-knowledge) продолжается.**

## 2026-10-05 - hardening fast lane: source_file, git-страховка, флаги, pyyaml

Аудит живого A/B-использования (репорт соседней сессии) вскрыл четыре дефекта fast lane, все закрыты в 0.4.0:

1. **Молчаливый мис-маршрут без source_file**: кандидат без `source_file` уезжает в дефолт `session/*.md` (4 факта от 04.10 легли туда). Контракт скилла дополнен: передавай `source_file`, когда файл очевиден; отдельные темы (vpn/) - не в личную базу.
2. **pyyaml отсутствовал в uv-tool-окружении** (установка 29.08, окружение не обновляется само; pyproject его объявляет): ленивый `import yaml` в `map_router._parse` ронял парсинг карты маршрутов → default-роутинг. Расхождения DB↔markdown не случилось (проверено: все 259 фактов в .md), но маршрутизация silently деградировала. Фикс: `uv tool install --force` из репо - зависимость из pyproject. Урок: после смены кода бинарь надо переустанавливать, смоук обязателен. (Позже выяснилось: причина misroute глубже - MapRouter вообще не был подключён в проде, см. 2026-10-06.)
3. **Флаг `--auto-yes` из док не принимался CLI** (реальные: `-y`/`--yes`) - агент по доке падал в интерактивный промпт без TTY. Найден своим же смоуком. CLI принимает алиас, доки переведены на канонический `--yes`.
4. **База писалась автоматами без ревью и без git** (репо ~/Documents/AI: 2 коммита за всю историю, весь рост - untracked; git-история как метрика A/B не существовала). Решение владельца: `curator save` после записи делает локальный git-коммит (без push, ремоутов у репо нет) - diff и точечный откат для автоматических правок; при saves вне репо - тихий скип.

**Статус: fast lane 0.4.0 (source_file + git-страховка), гейты 602+4 / harness 101, бинарь переустановлен, смоук зелёный.**

## 2026-10-03 - пивот: push-доставка отклонена, MCP-слой умирает, fast lane на CLI

Плановый разбор shadow-данных через 2 недели (18.09-03.10: 956 событий, 172 сессии, 24 пересечения порога 0.40 ≈ 9% сессий, все по теме - MVI/Compose/code-review, латентность медиана ~27ms). Данные сказали «срабатывания редкие, релевантные, дешёвые», но владелец вынес вердикт по ценности: **push-доставка в контекст не нужна** - «узкий кейс; если знанием не пользуюсь, доставка бесполезна». Гипотеза ADR 002/003 закрыта отрицательным результатом. #50 (live A/B) → отклонён; #49 (semantic retrieval) → заморожен: pull-путь тоже слаб (28 query, 57% промахов лексики, агент бросил запрашивать после 25.09 - query-тишина из-за качества, не забывчивости).

Смерть доставки тянет за собой серверный слой: **единственная возможность MCP, которую нельзя заменить скиллом+скриптами, была именно проактивная доставка в контекст**. Валидация, дедуп, маршрутизация, поиск, телеметрия - всё это функции над локальными файлами и DB, их дешевле делает CLI. Решено: MCP-сервер (регистрация в opencode.json), плагины curator-context и curator-reminder - **удаляются**; остаются CLI (`curator save` - fast lane), worker (дедуп/гигиена хранилища), карты, скилл curator-save. Нотификация на каждый session.idle признана шумом (нарушала собственный факт базы «шум в контексте ухудшает результат»); проактивное «может, сохраним?» в сессии остаётся - оно работает через блок в AGENTS.md, не через плагины.

Capture-церемония (session_capture → approve → curator-update-docs с preflight) уходит: медленно (3-5 мин на сохранение), три подтверждённых UX-бага (маршрут виден только после апрува; нет цикла правок - «candidates повторно не отправляй» читался как запрет; content_summary 1-2 предложения → тонкий контент). Вместо неё - fast lane: существующий `curator save` уже делает валидацию+дедуп+маршрут+запись (DB и .md, upsert по заголовку)+телеметрию одним вызовом; playbook curator-save переписывается под «леджер → показ что+куда → сразу сохранить» (без обязательного ревью-цикла: показ и запись одним ходом, пауза только при неоднозначности маршрута).

Выявлен раскол write-пути: два валидных скилла (curator-save MCP-флоу и старый save-knowledge) оба отвечали на «сохрни знания», агент выбирал случайно; записи save-knowledge (markdown напрямую) в хранилище не попадали - DB устарела с 26.09. Для чистоты сравнения подхват markdown→DB **не добавляем** до конца A/B.

**A/B на 2 недели (решение 03.10):** оба скилла живут параллельно, владелец зовёт какой хочет. Метрики разбора: кто кого (candidates.jsonl у куратора, git-история learnings у обоих), скорость, «не туда положил», пойманные дубли, достаточность контекста через неделю. Финальное решение о судьбе - по факту, не по теории.

**Открытые гипотезы к разбору (озвучены 03.10, НЕ решения):** (а) единица сохранения - файл/дока, а не карточка-факт: VPN-сессия сохранила целые доки через save-knowledge - и это работало хорошо; «карточка» была единицей доставки, доставка умерла - возможно, единицей снова становится файл; (б) возможный финал - 1 скилл + 2 карты (личная learnings + рабочая docs/ai проекта), дедуп по карте глазами агента, скрипты куратора - только если заболит; (в) рабочий контур (approach.md: design→plan→progress + docs/ai) - личная реализация spec-driven development, записи решений = ADR - конвергенция с практикой коллег (openspec), признак верного направления. Проектный write-back («проанализируй как работает X → разложи по docs/ai согласно карте») - ощущаемая владельцем потребность, отложена до конца A/B.

Критерий существования проекта: приватное репо, пишем для себя - «удобно владельцу» важнее гипотетических внешних юзеров. Ценность куратора - проверенная гипотеза с данными + выводы + живая механика (карты, дедуп, гигиена), а не продукт для других.

**Статус: MCP-слой и плагины удаляются, куратор живёт как CLI + worker + скилл curator-save (fast lane). A/B 2 недели → разбор → финальное решение.**

Поправка тем же днём (аудит фоновых хвостов по замечанию владельца): добиты пропущенные зомби — maintainer-крон (launchd 10:00, сломан с 19.09: zsh «can't open input file», exit 78, ноль пользы) и MCP-регистрация в hermes с мёртвым xmemory-бекендом (археология до ADR 001, watchdog держал сервер живым). Worker также выключен по решению владельца — полностью ручной режим: живой контур = только CLI-бинарь по запросу (`curator save` из скилла, `curator improve` руками), `curator start` вернёт воркер если понадобится. Из launchd остался один curator-env (CURATOR_BASE_DIR).

## 2026-09-18 - закрытие разработки

Аудит после сдачи (161 коммит за 2026-08-29 - 2026-09-18): retrieval recall 0.312→0.375, precision 1.0, leak 0, но delivery rate на корпусе не вырос (12.5%) → решили: разработку закрываем, включаем shadow-телеметрию, решение о live-доставке примем по живым данным. Эпик improve loop (#16/#34/#35/#36) закрыт как «отложено до shadow-данных», заведены и закрыты deferred #49 (semantic retrieval) и #50 (live A/B). Влит фикс: `curator_query` по умолчанию скрывает deprecated-факты - до этого они утекали агенту. Снесены пер-рановые JSON экспериментов 01-03: шум в репо, восстановимы из git.

Днём доведено до конца: личная база приведена к контракту (104 → 243 факта, style/ и tools/ в факт-формате, `###`-секции + мета), карта и каталог выровнены - 18 тем, чтение и запись симметричны (проверено: все 18 маршрутизируют верно, DB↔.md 243/243). Playbook save-knowledge дописан (`###`-контракт). Shadow включён в реальном конфиге, плагин curator-context на диске обновлён (копия была без фикса exitCode - inject был мёртв). Новые темы/файлы проверены тестом на tmp-копии: правка карты → рестарт харнеса → роутинг; новый .md → ingest → каталог.

При финальной верификации найден ещё один мёртвый контур: Desktop OpenCode (GUI) наследует PATH без `~/.local/bin` → плагин звал `curator`, получал exit 127 и молча глушил - живой телеметрии не было никогда. Фикс: плагин резолвит абсолютный фолбэк `~/.local/bin/curator`; env для GUI задан через `launchctl setenv` + LaunchAgent (переживает перезагрузки), `.zshenv` - для терминала. Попутно починена изоляция теста `_improve` от прод-env `CURATOR_BASE_DIR` (suite падал в окружении с глобальной базой).

Следом вскрылся полный Desktop-контракт OpenCode 1.18 (дебаг-плагином, по одной маскирующей друг друга несовместимости за раз): (1) автозагрузки из `~/.config/opencode/plugins/` нет - плагины обязаны быть в `plugin[]` конфига абсолютными путями, `file:///` и относительные пути не работают; (2) все экспорты модуля - функции (`export default async function`), любой не-функция валит загрузку молча; (3) Bun shell `$` в контексте фабрики недоступен (`ctx.$ === undefined`) - CLI зовётся через `node:child_process.execFile`. Плагины переписаны под контракт, инсталлер регистрирует их в `plugin[]` сам, контракт зафиксирован тестами (`test_opencode_plugin.py`, `test_installer.py`) и в `integrations/README.md`. Итог дня: живая shadow-телеметрия подтверждена - реальные сессии в `delivery-shadow.jsonl`, включая доставку карточек.

Вечером закрыты телеметрийные пробелы (аудит «логируются ли точки выбора»): shadow-события получили `ts` (без него delivery rate не строить по дням) и near-miss-кандидаты (топ-3 ниже порога 0.40 - прямые данные для подстройки порога и алиасов); каждый `curator_query` пишется в server.log (search/results/titles) - покрывает агентские «найди в базе» и ручной fallback. Плaintext-текст запроса - осознанный выбор против хэша: хэш лишает лог главного («что искали и где поиск молчал»); delivery-триггеры остаются хэшированы (сырой промпт). placement-кладка фактов логируется с вечера (topic/target/canonical_file).

**Статус: с 2026-09-18 продукт в реальном использовании, разработка остановлена. Фоном собирается shadow-телеметрия; решение о доработках (live-доставка #50, semantic #49, improve-петля #16) - по данным через 2-3 недели.**
