# Application Benchmark: переиспользует ли агент накопленный опыт

Эксперимент проверяет главное требование трека «Агент, который помнит»:
агент **копит опыт и переиспользует его в следующих задачах**.

## Что проверяли

10 кодинговых задач (агент дорабатывает легаси-код: добавляет DAO-метод,
переносит XML-разметку на Compose, чинит runtime-падение Dagger-фабрики).
В каждой задаче спрятано правило из нашей базы знаний — правило в задании
не названо, а окружающий код подталкивает к ошибке, которую это правило
запрещает. База выращена майнингом из 100 реальных рабочих сессий.

Сравнивались:
- **без памяти** — чистая модель решает задачу;
- **с Memory Curator** — правила из памяти доставлены в контекст сессии;
- промежуточный вариант — «просто файлы со знаниями», без обвязки
  (проверяли, не избыточно ли ядро).

Плюс 2 контрольные задачи: тривиальная (без применимого знания) и задача,
где правило применять **не надо** (проверка ложного применения).

## Результат

| | Все задачи | Задачи-ловушки (N=3) |
|---|---|---|
| Без памяти (чистая модель) | 8/10 | 0/6 |
| «Просто файлы со знаниями» | 9/10 | 3/6 |
| **С Memory Curator** (правила в контексте) | **10/10** | **6/6** |

Fisher exact (без памяти vs Memory Curator, ловушки): **p = 0.0011**.
Контроли: чисто во всех вариантах — ложного применения нет.

**Вывод:** в повторяющихся кодинговых задачах агент без памяти наступает на
одни и те же грабли — и даже файл со знаниями выручает через раз (агент
забывает свериться с ним, когда окружающий код «подсказывает» неверный путь).
Memory Curator — готовое к ежедневной работе решение: извлекает опыт из
реальных сессий, держит базу чистой (дубли, противоречия, устаревание)
и доставляет правила в контекст — агент применяет их в следующих задачах.

## Почему это честно

- Проверки — детерминированные скрипты (grep/структура кода), не мнение LLM.
  Заморожены sha256 ДО прогонов (`checks/FROZEN-original.sha`; два бага
  извлечения исправлены после просмотра решений, критерии не менялись —
  подробности в `results/report.md`).
- Задачи-ловушки прогнаны 3 раза каждое с независимыми агентами — результат
  воспроизводится без единого отклонения.
- Кейваты: основной прогон — по одному агенту на задачу; 8 из 10 задач
  решаются сильной моделью и без памяти (эффект проявляется на задачах,
  где знание противоречит «очевидному» решению); экспериментатор — автор
  задач и чеков. Полный список — `results/report.md`.
- Снимки решений всех прогонов закоммичены (`results/solutions/`) —
  таблицу можно перепроверить без запуска агентов.

## Воспроизведение

```bash
cd checks
python3 -c "
import sys; sys.path.insert(0, '.')
from pathlib import Path
import importlib
BASE = Path('../results/solutions')
for t in ['T01','T06']:
    mod = importlib.import_module('check_'+t)
    for run in [t, t+'R2', t+'R3']:
        r = [mod.check(BASE/run/a)[0] for a in ['arm_a','arm_b','arm_c']]
        print(run, r)
"
# T01/T06 — задачи-ловушки; R2/R3 — реплики; arm_a/b/c — без памяти / файлы / Memory Curator
```

Полный ре-ран с живыми агентами: развернуть фикстуры в три директории на руку
(`cp -R fixtures/T01/fix/. <arm_dir>/`), дать одинаковые задания (формулировки —
в `results/report.md`), решения прогнать чеками.

## Структура

```
fixtures/   task.md + fix/ — стартовое состояние задачи (нейтральный синтетический код)
checks/     детерминированные проверочные скрипты + sha-заморозка
results/    report.md (полная методология и кейваты)
            scoring-main-run.txt, scoring-replication.txt — выводы скоринга
            solutions/ — снимки решений всех рук для независимой верификации
```

## Заметки о валидности

- База знаний в репо не входит (рабочие знания команды). В прогоне использовалась
  замороженная копия verified-фактов, извлечённых майнингом из 100 реальных
  рабочих сессий (см. корневой README, раздел майнинга).
- N=1 на ячейку основного прогона; значимость обеспечивают репликации задач-ловушек.
