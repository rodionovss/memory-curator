# Experiment 03: Proactive Delivery — результаты

Дата: 2026-09-17. 192 прогона: 8 задач × 4 руки × 2 модели × 3 повтора.
Routing = R3 (победитель 01). O0/Q0 — переиспользование P0-прогонов
02 (конфигурация идентична).

## Главные результаты

**Application (pass):**

| Рука | strong | weak |
|---|---:|---:|
| O0/Q0 baseline (routing, без карточки) | 23/24 | 17/24 |
| O1 oracle-карточка (правильный факт) | 24/24 | **19/24** |
| Q1 реальный retriever (curator_context) | 24/24 | **14/24** |

**Q1 delivery rate: 6/48 (12.5%); silent: 42/48.**

## Выводы

### Part A: oracle-карточка работает

- T01 (скрытая ловушка withContext): **3/6 → 6/6** — правильная карточка
  закрывает самый жёсткий кейс полностью, включая слабую модель.
- Слабая модель в целом: +2 (17→19). Цена: лёгкий шум на консенсусных
  задачах (T07: 6/6→4/6) и контроле K2 (6/6→5/6).
- Механизм proactive delivery подтверждён: доставленный правильный факт
  применяется там, где routing не справляется.

### Part B: реальный retriever — бутылочное горлышко

- 42/48 прогонов — silent: текущий curator_context (threshold 0.4,
  lexical scoring) почти не находит карточки на реальных формулировках
  задач. Сходится с экспериментом 04 (recall 0.31).
- На T06 (единственная задача с релевантной выдачей) слабая модель
  упала 5/6 → 3/6: доставленная карточка summary-формата **вредна**
  слабой модели, когда summary неполно передаёт правило.
- Q1 weak итог 14/24 — хуже baseline: «плохая доставка хуже молчания»
  на слабых моделях.

### Итоговая формула

```
oracle card работает (T01 6/6)  →  доставка ценна
real retriever молчит 87.5%     →  узкое место — retrieval, не механизм
агент сам curator не зовёт (02) →  pull-путь мёртв
routing R3 уже даёт +14пп (01)   →  routing — главный работающий слой
```

## Решение (ADR 003)

1. Routing-слой (skill-метаданные в AGENTS.md) — primary delivery path.
2. Proactive plugin остаётся, но до улучшения retrieval его live-эффект
   около нуля (silence безопасен, вред — только при плохой выдаче).
3. Следующий рычаг — качество retrieval (threshold, reformulation-матчинг),
   не транспорт и не хранение.
4. Резидентный MCP curator не используется агентами (1/192 вызовов, 02)
   — переводится в debug/optional, не часть дефолтного сетапа.
