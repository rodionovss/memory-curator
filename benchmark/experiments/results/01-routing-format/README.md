# Experiment 01: Routing Format — результаты

Дата: 2026-09-17. 192 прогона: 8 задач × 4 руки × 2 модели (strong
`bifrost_GA/glm-5.3`, weak `bifrost_GA/GA.Qwen3.6`) × 3 повтора.
Изоляция: minimal opencode config (без глобального AGENTS/MCP/плагинов),
routing-поверхность = только workspace AGENTS.md + kb/.

## Главные результаты

**Application rate (детерминированные checks, memory-задачи):**

| Рука | strong | weak | все |
|---|---:|---:|---:|
| R0 без указателя | 21/24 | 15/24 | 73.8% |
| R1 personal-setup | 23/24 | 17/24 | 81.0% |
| R2 AGENTS-таблица | 24/24 | **14/24** | 78.6% |
| R3 skill-метаданные | 23/24 | 17/24 | **88.1%** |

**Навигация в kb (routing recall, найден файл факта):**

| Рука | strong | weak |
|---|---:|---:|
| R0 | 11/24 (находит glob-ом даже без указателя) | 4/24 |
| R1 | 20/24 | 9/24 |
| R2 | 21/24 | **3/24** |
| R3 | 20/24 | 9/24 |

## Выводы

1. **T01 (скрытая ловушка withContext) — ключевой кейс:** R0 = 0/6,
   любой указатель = 3/6. Ровно как в бенчмарке хакатона: без
   routing-инструкции агент не идёт в базу и повторяет баг.
2. **Сильная модель: потолок.** Любой формат даёт 23-24/24 — ей достаточно
   самого факта наличия указателя.
3. **Слабая модель: R2 (GoldApple-таблица) ВРЕДИТ.** application 14/24
   (хуже R0!), kb-навигация 3/24. Явная таблица trigger-слов сбивает слабую
   модель с толку (T02: 6/6 → 4/6; T04: 4/6 → 3/6). Гипотеза «стиль GoldApple
   лучше» НЕ подтвердилась для слабых моделей.
4. **R3 (skill-метаданные) — лучший баланс:** application 88.1% (все руки),
   T04 (простая-на-вид с правилом) 6/6, навигация как у R1, стоимость ниже R1.
5. **R1 (personal-setup указатель) дороже:** median tokens 20.3k против
   17.5-18.1k у R2/R3 — индирекция через index.md стоит лишнего чтения.
6. **Контроли чистые:** K2 false application 0/24 (исключение правила F72
   применено корректно во всех руках); K1 шум навигации 3/24 (12.5%).
7. **Latency не различается** (p50 11-13s по всем рукам).

## Решение для эксперимента 02

Routing-формат для access-path: **R3** (skill-метаданные).
