# Experiment 02: Access Path

## Вопрос

Что помогает агенту получить нужный факт после того, как задача уже дана:
обычный файл, curator tool, компактный индекс или готовый факт?

Routing format фиксируется в одном варианте до запуска эксперимента. Если
Experiment 01 завершён, использовать лучший вариант R1-R3. До его завершения
использовать R2, чтобы не смешивать access path с неявными ссылками.

## Варианты

| ID | Что получает модель |
|---|---|
| `P0` | Source files доступны, Curator отсутствует |
| `P1` | Доступен `curator_query/get`, компактного индекса нет |
| `P2` | Curator + каталог `topic -> trigger -> source`, полного факта нет |
| `P3` | В context заранее добавлен правильный полный факт |

Во всех вариантах corpus и task prompt одинаковы.

## Матрица запусков

`8 tasks × 4 variants × 3 repeats × 2 models = 192 runs`.

## Procedure

1. Запустить свежую сессию с одним вариантом P0-P3.
2. Отправить одну synthetic task.
3. Не подсказывать модели путь к правильному факту.
4. Записать route events: file read, curator query, curator get, index use.
5. Запустить deterministic application check.
6. Сохранить JSON result.

Для P3 карточка выбирается из `expected_fact_id`, а не настоящим retriever-ом.
Это намеренно: P3 измеряет пользу уже найденного факта, а не качество search.

## Метрики

- `fact_retrieval_rate`;
- `application_rate`;
- `manual_query_rate`;
- `index_use_rate`;
- `false_positive_rate`;
- `tool_calls` и `input_tokens`.

## Интерпретация

- P1 > P0: Curator tool помогает относительно прямого поиска файлов.
- P2 > P1: компактный индекс помогает выбрать правильный query.
- P3 > P2: указателя/индекса недостаточно, нужен полный факт в context.
- P1 ≈ P2: дополнительный индекс не нужен.
- P3 не выше P1/P2: проблема не в доставке, а в применении знания.

Не трактовать P3 как доказательство качества реального ranking: правильный
факт был выбран экспериментатором.
