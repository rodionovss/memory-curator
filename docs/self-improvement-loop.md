# Memory Curator — Контур самоулучшения

> Куратор улучшает память агента (improve-цикл внутри ядра). Этот сценарий —
> как сделать так, чтобы улучшался и сам куратор: баги и идеи от любых агентов
> собираются в один беклог, а разбирает их один уполномоченный мейнтейнер.

## Проблема

Любой агент в любой сессии, заметив баг куратора, хочет «быстро починить».
Несанкционированная правка живой системы памяти ломает все сессии сразу.
А единственный разработчик не хочет быть узким горлом: репорты должны
копиться и разгребаться фоном.

## Механизм (три роли, всё — файлы поверх продукта, 0 правок ядра)

```
любая сессия ──(скилл-репортёр)──> improve_backlog.md
                                          |
                                cron / вручную
                                          |
                                скилл-мейнтейнер (CURATOR_MAINTAINER=1):
                                  триаж → крит-баг: fix-ветка + тесты + лок. коммит
                                        → доработка: план
                                          |
                                отчёты + уведомление пользователю
```

1. **Файл-беклог** `improve_backlog.md` с контрактом записи:
   дата / сессия / серьёзность (крит-баг | доработка) / проблема /
   пруф / статус (`Открыта → В работе → Исправлена | Запланирована | Закрыта`).
   Дописывать может любой агент, статусы меняет только мейнтейнер.
   Отдельно от продуктового роадмапа (`design/backlog.md`); дубли против
   него проверяются при триаже.
2. **Скилл-репортёр** (загружается в любой сессии): заметил баг/идею —
   допиши запись по контракту, НЕ правь репо. Даёт импульсу «починить»
   легальный выход.
3. **Скилл-мейнтейнер** — единственный с правом правки. Цикл:
   триаж (дубль / нет пруфа / крит / доработка) → крит-баг: воспроизведи,
   fix-ветка от main, тесты, локальный коммит → доработка: черновик плана →
   сводный отчёт + уведомление. Вопросы, которые нельзя решить без
   человека, — в отчёт, решения не принимает сам.

## Гварды

- Мейнтейнеру **запрещён `git push`** всегда; мерджи в main и мердж
  чужих веток — решение человека.
- `main` не трогается: правки только в `fix/*`-ветках.
- **pre-commit hook**: коммит без env `CURATOR_MAINTAINER=1` блокируется —
  структурная отсечка «случайного» агента (не защита от намеренного
  обхода: агенты работают от одного пользователя ОС).
- Живая БД куратора — только после бэкапа.
- Инструкции-гейт в корне репо (AGENTS.md/CLAUDE.md): «ты не мейнтейнер →
  иди в беклог» — агент читает их в момент, когда открыл репо.

## Интеграция по расписанию

Пример — cron на macOS (launchd): обёртка раз в день проверяет беклог,
открытых записей нет — тихий выход; есть — запускает неинтерактивную
сессию мейнтейнера. Обёртка ставит `CURATOR_MAINTAINER=1` и проверяет,
что после прогона появился свежий отчёт (иначе — помечает прогон
провальным, даже если процесс вышел с rc=0).

Нюансы неинтерактивных сессий: доступ к каталогу репо должен быть разрешён
в permission-конфиге харнесса (external_directory), агент не может задавать
вопросы — всё неоднозначное уходит в отчёт.

## Известные ограничения

- Гейты — контракты + hook, а не права ОС: защищают от несчастного случая,
  не от злоумышленника. Полноценный RBAC — в продуктовом бэклоге.
- Скилл-репортёр — промпт-контракт: будущая фича — приём репортов самим
  ядром (MCP-тул с валидацией и дедупом), см. `design/backlog.md`.
