## Повод

Перечитали фидбек судей Hacker Sprint #2 → разбор «что мы на самом деле
построили» → аудит текущего read-path → смена фокуса продукта.

## Рамка: две проблемы (главный итог)

**Проблема 1 — СОХРАНИТЬ.** Уроки сессий не теряются, лежат там, где их найдут:
проектное знание → в репо проекта (docs/ai, README модулей, write-back куратора),
кросс-проектное → личная база learnings. Статус: в целом решена. Под-задачи:
качество извлечения (observer-эвал по cadence), лёгкая версия для Егора (без MCP).

**Проблема 2 — ИСПОЛЬЗОВАТЬ.** Следующая сессия узнаёт о сохранённом, читает,
применяет — и это измеримо. Статус: НЕ решена, сейчас главный фронт.
Под-проблемы: узнавание (каталог), отбор, применение (loaded ≠ used), метрика.

Накид Полищука — именно про разрыв между 1 и 2: «проверки состояния базы сами
по себе ещё не показывают улучшение агента». У нас самоулучшающаяся база;
самоулучшающегося агента пока нет.

## Что выяснил аудит (2026-09-16)

- Автоматически в каждую сессию грузится только PERSONAL_SETUP (карта
  Reference/Tools/Style + рабочая база) + правило «сверься с базой» из
  глобального AGENTS.md. Скиллы-механика: список name+description в промпте,
  тело по триггеру — работает на сотнях скиллов, копейки контекста.
- `learnings/session/` (12 файлов, ~90KB, факты куратора) в карту PERSONAL_SETUP
  не входит. SQLite (`~/.curator/knowledge.db`, 203 факта) при старте не
  читается; `curator_query` — только если агент сам догадался вызвать.
- Механика 9/10 промахов: правило есть, каталога нет — «слепой инструмент».
- Наш benchmark уже показал разрыв: файлы доступны, агент сам решает — 3/6;
  proactive-доставка — 6/6 (Fisher p=0.0011). Доступность ≠ применение.
- Старый save-knowledge уже имел каталог + маршрутизацию + индекс, но
  нестабильно: агент заводил новые файлы, дубли — знания расползались.
  Куратор добавил gatekeeper / dedup / карту / write-back — это его реальная
  ценность, не «умение сохранить текст».
- SQLite = индекс (dedup, поиск, статусы), НЕ источник контекста. Markdown =
  источник истины. Текущий curator-save так и работает — противоречия нет.

## Решения (принятые; не обсуждать заново без новых данных)

1. **xmemory — выпилить.** Нужен был только для хакатона. Выполнять отдельным
   пакетом ПОСЛЕ эксперимента (рука B может использовать текущий стек).
2. **MCP — необязательный адаптер**, не центр архитектуры. Новое не строим
   поверх MCP; основной путь — skill + CLI + локальный SQLite. Окончательную
   судьбу решат эксперимент и потребность multi-client (Егор).
3. **Формат:** один файл на тему, внутри атомарные секции-факты
   (Rule / Why / Tags). SQLite держит запись-на-факт для поиска и dedup.
4. **session/ — временное.** Растащить факты по тематическим файлам reference/
   (миграция), обновить reference/index.md и карту DOCUMENTATION-MAP.md
   (таргеты на новые пути). После миграции session/ удалить.
5. **GoldApple:** куратор = write-engine для существующих доков (write-back в
   docs/ai / README), НЕ вторая база. Каталог куратора для GoldApple не нужен:
   read-side уже закрыт картой AGENTS.md. Проектное знание живёт в репо.
   «Обёртка-скиллы на модули» = переизобретение AGENTS.md-карты — не делаем.
6. **Самоулучшение — целевая цель продукта**, не «потом». Строится по шагам:
   сохранение → доступность → применение → измерение. Откладывается только
   реализация слоя, если более дешёвый read-path уже даст эффект.
7. Личное и проектное — не разные продукты, а разные scope одного механизма.
   В личной базе почти всё — абстрактные знания; жёстко не разделяем.

## Что подсмотрели у других (референсы с выводами)

- **kata** — стартовый пакет 5–20 фактов + контракт использования + attribution
  «used_facts + decisions + diff». Уроки: precision ≠ transfer (пережатый отбор
  режет перенос урока); SessionEnd мёртв для записи; naive-дамп проверяет не то.
- **marginal-gain** — скоринг вес × уместность, порог на произведении, молчание
  с именованной причиной, потолки 5/1200, показ:польза = 1:6. Слой доставки
  переносим, но их константы не измерены.
- **cadence** — observer-эвал с закрытым словарём лейблов → метрики curator-save
  (проблема 1). «Вшивать правила всем» — анти-паттерн масштаба.
- **snowball** — keyed read strictest-first, ≤3 факта, paired-эвал на 50
  held-out сценариях (референс для масштаба). Чтение по ключу надёжнее семантики.
- **SkillOpt-Sleep (Microsoft)** — ночной цикл harvest→mine→replay→gate→adopt.
  Их результат: ungated самоулучшение коллапсирует (0.55→0.03), гейт обязателен.
  Независимо подтверждает наш capture→gatekeeper→approve. Доставку не решают
  (у них один выученный документ).
- **Windsurf `model_decision` rules** — каталог описаний в промпте, полный
  текст агент читает при совпадении с задачей. Идея «как со скиллами» уже в проде.
- **agentmemory #457** — наш кейс 9/10 слово в слово: «lessons sit dormant,
  agent must think to call». Их фикс — авто-инъекция ранжированного блока.
- **opencode-механика доставки** (разведана, для руки D): хук `chat.message`
  (даёт текст первого сообщения до генерации) +
  `experimental.chat.system.transform` (пуш в system prompt того же хода).
  Фолбэк — инъекция TextPart. Хуки без try/catch валят pipeline — оборачивать.

## Эксперимент (главный следующий шаг)

Сравнить read-path на дискриминирующих задачах по образцу benchmark/application:

- **A** — Personal Setup + файлы (агент сам решает читать) — текущий baseline;
- **B** — curator_query вручную (агент сам решает вызвать) — текущий MCP-путь;
- **C** — каталог из SQLite при старте (title + описание-триггер + путь; как
  скиллы), полные факты — по дёрганью `curator get`;
- **D** — автоматическая доставка релевантного факта (механика разведана).

Метрики: прочитано / применено / повтор ошибки / ложное применение /
добавленный контекст / стоимость. Гипотеза A ≈ B < C ≈ D — проверять, не
предполагать. Каждая рука отдельно, комбинации (A+B в одной руке) запрещены —
иначе не разберём, что помогло.

## Разделение моделей (execution protocol)

- **Сильная модель** — архитектура, дизайн эксперимента, интерпретация,
  ревью diff, опасные операции (выпил xmemory), решения.
- **BF glm-5.3** (`bifrost_GA/glm-5.3`) — ограниченные механические пакеты:
  инвентаризация, миграция, замеры, тесты. Без права архитектурных решений.
- Переключение по пакетам, не по шагам. Fallback нет: модель недоступна —
  пакет стоп и отчёт об ошибке.
- Запуск BF-пакета: `opencode run -m bifrost_GA/glm-5.3 "<задание>"` или
  сессия с переключённой моделью; задание = текст Task N из плана.

## Открытые вопросы

- Хватит ли A, или нужен C/D — решает эксперимент.
- Судьба MCP после эксперимента (рука B его использует; вопрос multi-client).
- Егор: лёгкий save-скилл без MCP — отдельный трек, вместе с ним.
- Метрики curator-save (observer-эвал cadence) — параллельный трек проблемы 1.
- Наполнение: каталог станет полезен для рабочих задач, когда в базе появятся
  рабочие факты (миграция session/ — первый шаг; дальше capture в сессиях).
