# Пример работы агента до и после обучения

> Форма — текстовые логи (правила допускают «видео / логи / любая другая форма»).
> Всё ниже — реальные выводы команд, воспроизводятся одной командой: `curator demo --keep`.

## 1. Одни и те же сессии: чистая память vs обученная

Первая сессия прошла и сохранилась. Прогоняем те же сессии ещё раз —

**ДО (чистая память)** — знания принимаются:

```
── Kotlin/JVM debrief ──
  Извлечено фактов: 2
  Clean (пустая память):
    Одобрено: 2 ['JvmInline value class внутри sealed interface бесп...',
                 'Data class предпочтительнее value class в общем сл...']
    Отклонено: 0
```

**ПОСЛЕ (обученная память)** — те же знания распознаются как дубликаты,
новые темы — принимаются:

```
── Kotlin/JVM debrief ──
  Trained (2 фактов):
    Одобрено: 0
    Отклонено: 2
    Причины: Дубликат: уже есть 'JvmInline value class внутри sealed interface...'
             Дубликат: уже есть 'Data class предпочтительнее value class...'

── Compose ImmutableList ──   (новая тема — не дубликат)
  Trained:
    Одобрено: 1 ['Когда ImmutableList нужен, а когда — оверхед']
```

**Вывод:** агент с обученной памятью ведёт себя иначе — он не сохраняет
уже известное и принимает только новое. Поведение изменилось опытом.

## 2. Полный цикл жизни знания (`curator demo --keep`)

Одна команда прогоняет весь жизненный цикл — реальные вызовы, изолированная база:

```
ЭТАП 1/6 · GATEKEEPER: валидация кандидатов + сохранение
  Одобрено: 7 (инструменты, технические и доменные правила)
  Отклонено: 3
    ⛔ Поправить верстку кнопки на экране входа — фичевая деталь, не знание
    ⛔ Правка UI — слишком короткий заголовок
    ⛔ Пагинация списков через cursor параметр в API
       — вероятный дубликат: уже есть '...offset параметр в API'
  Итого: принято 7, отклонено 3

ЭТАП 2/6 · WRITE-BACK: знания вернулись в .md документацию
  Созданы файлы: index.md, session/reference.md, session/tool.md

ЭТАП 4/6 · IMPROVE LOOP: дубликаты + противоречия (автономно)
  Дубликатов найдено: 1
    ↔ 'Доменное правило про пагинацию...' ~ 'Альтернативное правило про пагинацию...'
      консолидация: проигравший помечен deprecated (eval gate одобрил)
  Противоречий найдено: 1
    ✅ победил: 'Командное правило использовать Retrofit' (больше тегов 2 > 1)
    ⛔ проиграл: 'Рабочая гипотеза не использовать Retrofit' → deprecated

ЭТАП 5/6 · ТЕЛЕМЕТРИЯ: что реально читают (совет, не приговор)
  Часто запрашиваемые (2): Data class… (12×), MCP SDK v2… (5×)
  Не запрашивались >30 дней (1): ⏳ MCP SDK v2…
  Решение за человеком: таймерного decay нет — время не делает факт ложным.

ЭТАП 6/6 · ИТОГ: 7 фактов = 5 verified / 0 hypothesis / 2 deprecated
```

## 3. Дельта на кодинговых задачах: без памяти / с Memory Curator

48 прогонов чистых агентов: 10 кодинговых задач-ловушек (агент дорабатывает
легаси-код; каждая кодирует одно правило базы, правило в задании не названо,
ловушка — в окружающем коде) + 2 контроля + 2 задачи-ловушки × 3 реплики.
Проверки — предрегистрированные детерминированные скрипты, замороженные до
прогонов. Полная методология: [benchmark/application/](../benchmark/application/).

| | Без памяти | «Просто файлы» со знаниями | **Memory Curator** |
|---|---|---|---|
| 10 задач-ловушек | 8/10 | 9/10 | **10/10** |
| Задачи-ловушки ×3 (T01, T06) | 0/6 | 3/6 | **6/6** |
| Fisher exact | | | **p = 0.0011** |
| контроли (ложное применение) | чисто | чисто | чисто |

Ключевой кейс T01 — «добавь DAO-метод, следуй существующему стилю», где весь
файл уже оборачивает suspend-DAO в `withContext(IO)` (антипаттерн по правилу
базы):

- агент без памяти повторил антипаттерн — 3 раза из 3
- агент со «просто файлами» **имел всю базу из 66 фактов** (60 майнинг + 6 живых)
  — и повторил антипаттерн 3 раза из 3: не стал искать, потому что окружающий
  код «подсказывает» ошибочный ответ
- агент с Memory Curator (правило доставлено в контекст) — применил 3 раза из 3

**Вывод: без памяти агент повторяет старые ошибки; знание, которое лежит
мёртвым грузом, применяется нестабильно; правило, доставленное в контекст
задачи, — применяется.**

## 4. Живая база автора (не демо)

Прод-использование во время спринта — реальные знания из реальной работы:

- Майнинг архива: 100 реальных рабочих сессий → 181 кандидат → 174 факта-гипотезы
  → ревью человеком → **60 verified** (precision майнинга 99.4% по дублям,
  выживаемость после строгого ревью 35% — и это честная цифра)
- База: 66 verified-фактов (60 из майнинга + 6 живых), 10 тематических файлов
- `curator status`: improve-цикл активен; на чистой базе честно возвращает нули

## Как воспроизвести

```bash
git clone https://github.com/podlodka-ai-club/refinement.git && cd refinement
./install.sh          # установка одной командой
curator demo --keep   # весь цикл выше + файлы для осмотра
curator status        # состояние памяти
```

Сценарии «до/после» — `core/curator/demo.py` (`run_demo`, `run_time_lapse`),
вызываются в туре `curator demo`.
